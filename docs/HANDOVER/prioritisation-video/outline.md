## 7. dynamic — Re-planning as work moves (6 steps · ~60s)

**Information pool:**
- Stage fields: status · % complete · actual start / end · remaining override · blocked reason — article §7
- Formula: remaining = ceil(duration × (1 − % complete)) — article §7
- Rules: Done = fixed history; In Progress keeps its start and schedules the tail; Blocked holds its successors — article §7
- Flow: edit → schedule stale → Recalculate → new immutable run version — article §7
- Badges: On Track · At Risk · Off Track · Blocked · Left Out — article §7

**Plan:**
- step 1 (~11s) — One project's 14 stages, with status chips and a % fill on each
- step 2 (~11s) — Next run: Done stages lock in grey, the In-Progress stage keeps its start and only its tail moves
- step 3 (~7s) — One stage turns Blocked, and every later stage holds behind it
- step 4 (~10s) — "Stale" flag rises on the project, then the Recalculate button is pressed
- step 5 (~10s) — Run versions stack: v1, v2, v3; the older ones stay frozen and readable
- step 6 (~11s) — The five health badges, each derived from the run (arrow from "Run" to badge, with no manual input)

> "Updating progress never quietly reshuffles the portfolio."
